# CommuteCircle reliability audit — 14 November 2026

Scope: authentication/session recovery, journey discovery and time boundaries,
legacy compatibility, reservation/approval/boarding transitions, sandbox refunds,
private circles, recurring schedules, chat, notifications, foreground GPS,
database constraints/migrations, deployment wiring, and responsive workspaces.
This is a source and regression audit, not a guarantee that all defects are absent.

## Confirmed defects corrected in 0.2.6

| Priority | Trigger and previous behavior | Correction and evidence |
|---|---|---|
| P1 | A pickup is exactly midnight at the start of the requested local travel day. Search excludes it, including intermediate stops on an overnight route. | Search includes the start of the requested window, excludes its end, and still rejects already-departed pickups. Six failing-then-passing API cases cover UTC, India and New York, at initial and intermediate stops. |
| P1 | Verification is required, but a client posts a new offer through deprecated `/v1/rides`. The endpoint accepts an offer without an approved vehicle. | Under that policy, new legacy offers return a clear 409 directing callers to `/v1/journeys`. Existing history and cancellation remain usable. Regression verifies both enforcement and compatibility. The deployment's verification policy is not changed by this release. |
| P1 | A slow commute save finishes after the user has navigated away and entered another route. The old response overwrites the current planner state. Save and delete can also overlap. | Serialize profile writes, lock related controls while pending, retain fields after failure, and invalidate the saved-commute cache after a detached write without changing the new route. Browser cases cover delayed success and failed-save retry. |
| P1 | A station catalogue request never completes. Place search waits for it before contacting the online provider. | Five-second bounds and screen cancellation now apply to catalogue/configuration reads. A stalled local shard falls through to online search. Node tests exercise timeout and cancellation. |
| P2 | Road routing succeeds but the optional public-stop catalogue fails, or a long route geometry exceeds the JavaScript function-argument limit. | Preserve the measured route with an explicit warning when optional suggestions fail. Compute geometry bounds incrementally. Regression uses 180,000 coordinate samples. |
| P2 | The full navigation stops wrapping at 1151px, before the header has room for its links and account action. Full labels also crowd the 721px tablet boundary. | Keep navigation on its own row through 1280px and use short visible labels through 950px, retaining full accessible names. Test both sides of the breakpoints. |
| P2 | Long recurring-route names force mobile grids wider than the screen; seven weekday choices cannot fit in one row. Small headers and trip summaries also compete for space. | Allow grid children to shrink, wrap long names and weekday choices, and give the mobile brand/account row enough room while retaining touch targets. |

## Validation

- Before changes: 193 API checks passed locally with 93.35% coverage. Fourteen
  PostgreSQL-only concurrency/migration cases skip on SQLite and must run in CI.
- Seven new backend boundary/policy regressions initially failed and then passed.
- Full local API run: 200 passed, 14 PostgreSQL-only skips, 93.36% coverage.
- Nine focused JavaScript recovery/privacy/transport checks passed locally.
- The PR's required `API checks` job is the release gate: PostgreSQL migration
  upgrade/check/downgrade/upgrade, the full API suite, browser flows, static-package
  validation, and runtime-container build.
- Browser coverage adds save/navigation races and phone/tablet/desktop widths
  320, 360, 390, 540, 720, 721, 768, 950, 1024, 1150, 1151, 1280, 1281 and 1440 across
  booking, offering, circles, recurrence, trips, messages and profile. See the
  job result for executed evidence, rather than treating test source as a pass.
- Render's error-level logs for the preceding day and recent failure events were
  empty when inspected on 14 November. This does not establish a load or uptime SLO.
- No new schema migration, production-data cleanup or palette change is included.

## Remaining product and operational limits

| Area | Current limit | Next required work |
|---|---|---|
| Real payments | Accounting and refunds are sandbox-only. | Payment-provider integration, signed webhooks and reconciliation before collecting money. |
| Worldwide operation | Map search accepts international places, but pricing is INR and recurring schedules are explicitly Asia/Kolkata only. The offline catalogue is India-focused. | Currency/timezone product design, DST scheduling rules and wider pickup data. |
| Trip exceptions | No-shows, driver interruption after departure and disputes have no complete resolution workflow. | Define ownership, passenger remedies and audited transitions before expanding the pilot. |
| Recurrence | A user action generates only the next 14 days. | A reliable scheduled job with retry/monitoring before advertising unattended recurrence. |
| Verification | Evidence is reviewed manually outside this application. | Staff onboarding, evidence handling and operations. Do not turn on a flag and describe it as automatic identity verification. |
| Notifications | Email/SMS/WhatsApp need configured providers and verified opt-in destinations. | Verify actual provider delivery separately. An outbox record is not proof of delivery. |
| GPS | Browser updates depend on location permission and foreground execution. | Real-device checks and a separate native/background tracking design if required. |
| Production operations | GitHub Pages and the existing Render service are the live pilot. | Record backup restoration and rollback drills, load measurements, dependency/image scanning and reliable automated promotion. |

Priority refers to user impact in this audit. Unconfigured product capabilities
are listed separately from reproduced code defects. No live users were booked,
charged, messaged or added to circles during these checks.
